\section{Objetivo de la guía}

Esta guía explica cómo compilar, ejecutar y probar el evaluador de expresiones desarrollado para el trabajo final. El programa permite escribir expresiones matemáticas en una variable principal \texttt{x}, evaluarlas en un punto y calcular su derivada mediante números duales.

Aunque el uso más directo es como calculadora, internamente el proyecto está organizado como un DSL/EDSL. La entrada textual se parsea a un árbol de expresiones, ese árbol puede optimizarse, evaluarse, imprimirse y derivarse automáticamente. Por eso la guía no sólo muestra comandos, sino también qué espera el programa en cada modo de uso.

\section{Requisitos y ubicación}

Para usar el proyecto hace falta tener GHC y Cabal instalados. Los comandos están pensados para ejecutarse desde la raíz del repositorio. En PowerShell, por ejemplo:

\begin{codeblock}
cd C:\Users\lucho\ALP-2025-LCC
\end{codeblock}

El proyecto también puede compilarse desde WSL. Esto es útil especialmente para compilar los documentos LaTeX, aunque los comandos de Cabal funcionan normalmente desde PowerShell.

\section{Compilación}

El primer paso recomendado es compilar todo el proyecto:

\begin{codeblock}
cabal build all
\end{codeblock}

Este comando compila la biblioteca, el ejecutable y lo necesario para los tests. Si Cabal responde \texttt{Up to date}, significa que no detectó cambios pendientes de compilación. Si hubo modificaciones en algún módulo, Cabal recompila sólo lo necesario.

\section{Modo interactivo}

El modo interactivo está pensado para probar una expresión por vez. Se inicia con:

\begin{codeblock}
cabal run ALP2025-LCC
\end{codeblock}

El programa primero pide una expresión. Si el parser la acepta, muestra la expresión normalizada por el pretty printer y, cuando corresponde, también su versión optimizada. Después pide el valor de \texttt{x} y calcula dos resultados: el valor de la función y la derivada en ese punto.

\begin{codeblock}
>>> sin(x) + x^2
>> Ingrese el valor de x: 1
f(1) = 1.8414709848078965
f'(1) = 2.5403023058681398
\end{codeblock}

El valor ingresado para \texttt{x} puede ser un número o una expresión constante como \texttt{pi/2}. Para salir del modo interactivo se puede escribir \texttt{salir}, \texttt{quit} o \texttt{exit}.

\section{Procesamiento de archivos}

El modo archivo permite ejecutar varios casos en una sola corrida. Cada línea útil tiene el formato:

\begin{codeblock}
expresion @ valor_de_x
\end{codeblock}

La parte izquierda se interpreta como expresión del DSL. La parte derecha se usa como valor de \texttt{x}. Por ejemplo:

\begin{codeblock}
x^2 + 2*x + 1 @ 3
sin(x) @ pi/2
log(x) + pi @ e
\end{codeblock}

Para procesar un archivo se usa:

\begin{codeblock}
cabal run ALP2025-LCC -- -f examples\basico.txt
\end{codeblock}

También existe la opción larga:

\begin{codeblock}
cabal run ALP2025-LCC -- --file examples\basico.txt
\end{codeblock}

En algunas instalaciones de Windows puede fallar la ejecución directa del binario generado por Cabal por políticas del sistema. En ese caso se puede correr el mismo flujo con \texttt{runghc}:

\begin{codeblock}
cabal exec -- runghc -isrc -iapp app\Main.hs -f examples\defensa.txt
\end{codeblock}

\section{Comentarios en archivos}

Los archivos aceptan comentarios de línea y comentarios de bloque. Esto permite armar ejemplos explicativos sin que esas aclaraciones formen parte de la expresión.

\begin{codeblock}
-- Esto es un comentario
x^2 @ 3 -- comentario al final de la linea
\end{codeblock}

\begin{codeblock}
{- Comentario
   de varias lineas -}

(x + {- comentario interno -} 1) * 2 @ 3
\end{codeblock}

Los comentarios se limpian antes de parsear cada línea. Si una línea queda vacía después de quitar comentarios y espacios, se ignora.

\section{Sintaxis del lenguaje}

El lenguaje soporta los operadores aritméticos \texttt{+}, \texttt{-}, \texttt{*}, \texttt{/} y \texttt{\^{}}. El signo menos puede usarse como resta binaria o como menos unario. La precedencia que usa el parser es:

\begin{codeblock}
potencia > menos unario > multiplicacion/division > suma/resta
\end{codeblock}

Esto significa que \texttt{-x\^{}2} se interpreta como \texttt{-(x\^{}2)}. Si se quiere elevar el negativo completo, hay que escribir \texttt{(-x)\^{}2}.

Las funciones soportadas son:

\begin{codeblock}
sin, cos, tan
sinh, cosh, tanh
arsinh, arcosh, artanh
sqrt, exp, log
\end{codeblock}

También se reconocen las constantes \texttt{pi} y \texttt{e}. Estas constantes pueden aparecer tanto en la expresión como en el valor ubicado a la derecha de \texttt{@}.

\section{Dominios y errores}

El evaluador trabaja sobre números reales. Por eso algunas funciones tienen restricciones de dominio. \texttt{log(x)} requiere argumentos positivos y \texttt{sqrt(x)} no acepta valores negativos. Para las funciones inversas hiperbólicas, \texttt{arcosh(x)} requiere \texttt{x >= 1} y \texttt{artanh(x)} requiere \texttt{|x| < 1}. La tangente se rechaza en puntos donde el coseno es cercano a cero.

Cuando ocurre un problema, el programa devuelve un error controlado. Por ejemplo:

\begin{codeblock}
sqrt(-1) @ 0
\end{codeblock}

produce:

\begin{codeblock}
[X] Error al evaluar: Error de dominio: sqrt requiere argumento no negativo
\end{codeblock}

También se detecta división por cero:

\begin{codeblock}
1/0 @ 0
\end{codeblock}

y variables no definidas:

\begin{codeblock}
y + 2 @ 1
\end{codeblock}

El modo de usuario está centrado en \texttt{x}. Si aparece otra variable sin valor asociado en el entorno, se informa como variable no definida.

\section{Optimización}

Antes de evaluar, el programa aplica optimizaciones simples sobre el AST. Por ejemplo, puede transformar \texttt{x + 0} en \texttt{x}, \texttt{x * 1} en \texttt{x}, o calcular \texttt{2 + 3} como \texttt{5}. Estas reglas hacen que algunas expresiones se muestren de forma más limpia y prueban que el árbol puede transformarse antes de interpretarse.

La optimización es conservadora. No se aplican reglas como \texttt{x/x = 1}, \texttt{x*0 = 0} o \texttt{x\^{}0 = 1} en todos los casos, porque podrían ocultar errores. Por ejemplo, si \texttt{x = 0}, la expresión \texttt{x/x} debe seguir dando división por cero. Esta decisión es importante: el optimizador no debe cambiar una expresión que falla por otra que parece válida.

\section{Archivos de ejemplo}

La carpeta \texttt{examples/} contiene archivos preparados para probar partes distintas del lenguaje. \texttt{basico.txt} muestra expresiones iniciales, \texttt{compuestas.txt} combina funciones, \texttt{constantes.txt} usa \texttt{pi} y \texttt{e}, \texttt{optimizaciones.txt} muestra reglas conservadoras, \texttt{casos\_error.txt} fuerza errores controlados y \texttt{defensa.txt} reúne casos útiles para explicar el trabajo.

Una corrida recomendada para revisar varias decisiones juntas es:

\begin{codeblock}
cabal exec -- runghc -isrc -iapp app\Main.hs -f examples\defensa.txt
\end{codeblock}

Ese archivo muestra precedencia, derivación automática, optimización, errores de dominio, constantes y comentarios dentro de expresiones.

\section{Pruebas}

La suite completa se corre con:

\begin{codeblock}
cabal test
\end{codeblock}

En Windows, si la ejecución del binario de test queda bloqueada, se puede usar:

\begin{codeblock}
cabal exec -- runghc -isrc test\TestSuite.hs
\end{codeblock}

La suite actual contiene 138 casos. Además de probar evaluación básica, derivadas, parser y errores, incluye una verificación llamada:

\begin{codeblock}
Verificacion de Casos de ejemplo
\end{codeblock}

Esa prueba lee todos los archivos \texttt{.txt} de \texttt{examples/}. La intención es que los ejemplos usados para mostrar el trabajo también estén cubiertos por la validación automática.

\section{Notas finales}

El proyecto no busca ser un sistema de álgebra computacional completo. Su foco es representar un lenguaje pequeño, interpretarlo de forma segura y usar números duales para obtener derivadas automáticamente. Las decisiones de diseño priorizan robustez y claridad por encima de agregar funcionalidades sin conexión con el objetivo del trabajo.
